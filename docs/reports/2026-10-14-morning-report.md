## 2. 보드 준비 (펌웨어)

- **보드 정체:** Keyestudio ESP32 PLUS(KS5020), ESP32-D0WD-V3, 4MB 플래시, CH340 USB(VID 0x1A86 / PID 0x7523). 전용 부트로더·잠금 없음. Keyestudio 공식 KS5020 MicroPython 튜토리얼 2-1-4가 Thonny(esptool)로 범용 `ESP32_GENERIC` 펌웨어를 굽도록 안내하므로, erase/flash는 제조사가 의도한 절차입니다. "Hard resetting via RTS pin"은 재부팅 메시지일 뿐입니다.
- **전 상태:** 부팅 뒤 `Ready`만 출력하고 REPL에 답하지 않는 아두이노 스케치. 이 스케치는 지워졌고(소스가 없으면 복구 불가), Arduino IDE로 다시 올릴 수 있습니다.
- **구운 것:** `ESP32_GENERIC-20260824-v1.29.0.bin`(erase_flash 1.6초, write 29.8초, 해시 검증). pyserial로 `>>>` 프롬프트와 `MicroPython v1.29.0` 확인.
- **v1.29.0 호환 검사(보드에서 직접 실행):** 번들 라이브러리 9개 import OK(ssd1306·gfx·keypad·irrecvdata·soft_iic·mfrc522_config·lcd128_32·lcd128_32_fonts; mfrc522_i2c는 제 테스트 스크립트가 32KB를 한 번에 보내 MemoryError — 앱은 512자씩 나눠 쓰므로 무관), `PWM.duty/duty_u16`, `ADC.atten/width/read/read_u16`, `SoftI2C`, `I2C(0)`, `utime`, `time.ticks_*`, `framebuf`, `const()` 모두 OK. **나중에 같은 두 명령으로 다시 구워도 됩니다.** Keyestudio 문서의 v1.24.1로 내려도 같은 API입니다(파일 받아 둠).

## 4. 블록 설명 팝업과 블록 사전 (계획 4)

설계 `docs/superpowers/specs/2026-10-14-block-docs-design.md`, 계획 `docs/superpowers/plans/2026-10-14-plan4-block-docs.md`. 요청이 "팝업 또는 docs 페이지"였는데 둘 다 만들었습니다(같은 데이터를 공유하므로 추가 비용이 작음).

### 4.1 쓰는 법
- **팝업:** 작업판이나 팔레트의 아무 블록이나 **우클릭 → "이 블록 설명 보기"**(맨 위 항목). 팝업에 ① 블록 제목(학생이 적은 값 그대로), ② "내 블록이 만드는 코드"(그 블록의 지금 값으로 생성한 MicroPython), ③ "무슨 뜻인가요"(2~4문장), ④ "예시 프로그램", ⑤ "알아 두기"(주의점). 버튼: "블록 사전에서 보기"(새 탭), 자유 코딩에서만 "예시를 편집기에 열기"(작업판을 바꾸기 전에 확인창).
- **블록 사전:** 상단 메뉴 **블록 사전**(`#/docs`). 왼쪽 카테고리(툴박스 순서·색·개수), 검색(제목·코드·설명 포함 검색, "N개"), 카테고리별 카드(제목 칩, 코드, 뜻, 예시 접기/펼치기, 팁, "이런 이름으로도 나와요"). 카드의 "편집기에서 열어 보기"는 `#/lab?example=<블록>`으로 예시를 작업판에 싣습니다. `#/docs?block=<블록>`으로 들어오면 그 카드로 스크롤·강조.

### 4.2 만든 방식
- `src/docs/catalog.ts`: 툴박스를 돌며 블록 종류마다 헤드리스 Blockly 작업판에 블록을 만들어 **제목(필드·그림자 값)과 코드를 자동 생성**합니다. 코드는 생성기의 새 공용 함수 `blockSnippet(block)`(준비 줄 + 도우미 + 그 블록 코드)에서 옵니다. 그래서 블록 정의가 바뀌면 사전도 따라 바뀝니다.
- `src/docs/content/*.ts`: 105개 블록의 **손으로 쓴** 개념·예시·팁(핵심 7 카테고리 + 하드웨어 8 카테고리).
- **테스트로 강제하는 것:** 툴박스의 모든 블록에 내용이 있고, 제목에 `%n`이 남지 않고, 코드가 비지 않고, **모든 예시가 블록으로 되돌아간다**(`codeToBlocks` 결과에 code_stmt/code_expr 없음), 설명은 2~4문장·"이 블록은"으로 시작하지 않음·이모지 없음.
- 팝업: `Blockly.ContextMenuRegistry` 항목 → `BlocklyWorkspace.onDocRequest` → shadcn Dialog(`BlockDocDialog`). 사전: `src/app/docs/`. Blockly는 별도 청크(`blockly-*.js`)로 분리해 설명 글만 고쳐도 큰 파일을 다시 받지 않게 했습니다.

### 4.3 리뷰에서 잡아 고친 것 (원장 Ruling 32~43)
- 예시 제목 방향 오류(RGB), 조이스틱 방향은 배선에 따라 달라 high/low로, LCD 주소·칸 범위, IR 값 꼴('0xff00ff' 글자)과 1초 지연 팁, 소리 센서 기준값 팁, 서보 "신호의 길이" 문구.
- "블록 사전에서 보기"가 같은 창으로 이동해 **작업판을 잃고 보드가 끊기는** 문제 → 새 탭으로(설계 §3 수정).
- 팝업 제목이 툴박스 기본값을 보여 주던 것 → 학생 블록의 실제 값으로.
- 카테고리 색 위 흰 글자의 대비 부족(1.9:1 등) → 색마다 흰/검정 중 대비가 높은 쪽을 고르고 테스트로 4.5:1 보장.
- 두 번째 카테고리에만 나오는 블록(센서의 값 읽기, 부저·릴레이 켜기)이 사전에서 안 보이던 것 → "이런 이름으로도 나와요".
- 접근성: 카드 제목 h3, 예시 펼침 버튼에 블록 이름 aria-label, 결과 수 aria-live, 딥링크 포커스.

### 4.4 리뷰가 찾은 앱 결함: OLED 선·네모 블록
Keyestudio가 배포한 `ssd1306.py`는 `framebuf`를 상속하지 않아 `line`/`rect`가 없습니다. 따라서 **OLED 선 긋기·네모 블록은 지금까지 보드에서 AttributeError**였습니다(단위 테스트는 코드 생성만 보므로 못 잡음). `ba9cbbf`에서 micropython-lib 공식 `ssd1306.py`(MIT, 같은 생성자·text/show/fill + line/rect/hline/vline/fill_rect)로 교체했고, `2ddb6f5`로 이미 옛 판이 든 보드에도 새 판이 올라갑니다. 이 파일의 라이선스 문제도 함께 해소됐습니다(README 갱신). **실보드에서 OLED로 확인해야 할 항목입니다.**

## 5. 실제 보드 체크리스트 — 대기 중인 이유와 푸는 법

- Claude 앱 내장 브라우저는 Web Serial **포트 선택 창을 띄우지 못합니다**(Electron 제한). 그래서 Claude in Chrome 확장으로 선생님 Chrome을 조작하는 방식으로 바꿨고, 확장은 연결됐습니다.
- 그런데 선생님 Chrome의 **다른 탭(제가 볼 수 없는 탭)이 보드 포트를 잡고 있어**(`lsof`로 Google Chrome이 `/dev/cu.usbserial-10`를 열고 있음) 제 탭에서는 `open`이 실패합니다. Web Serial 권한은 이미 배포 origin에 허락돼 있어서, 그 탭이 포트를 놓는 순간 **사람 손 없이** 연결·검증이 가능합니다(§3의 자동 연결 덕분).
- **해 주실 일:** 블록랩이 열린 다른 Chrome 탭에서 "끊기"를 누르거나 탭을 닫아 주세요. 10초 안에 제가 감지해 아래 20항목을 자동으로 돌리고 이 보고서에 결과를 덧붙입니다.

체크리스트(밤샘 보고서 §5와 같음): 연결 배지 "연결됨" / 샘플(LED 깜빡이기) 실행·보드 LED / 멈춤 / NameError 코드 실행 → 콘솔 Traceback(영어)과 줄·블록 강조 / 빠른 print 반복 / 한글 출력 / "보드에 저장"으로 main.py + 라이브러리 업로드(ssd1306 새 판으로 바꾸기 포함) / 전원 재인가 뒤 main.py 자동 실행 / 끊기·다시 연결 / 실행 중 뽑기 / OLED 선·네모 블록(§4.4) / 트랙 run 단계에서 실행.
