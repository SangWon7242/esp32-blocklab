## 1. 한눈에 보기 — 어디로 가져가는가

| 구분 | 개수 | 내용 |
|---|---|---|
| ESP32 교안으로 **그대로** | 13차시 | 센서·부품이 키트에 있고 구조도 같은 것 (예: 재난 알리미, 랜덤 망치, 온습도 알리미, 멜로디 버저, 인터럽트, 안전선풍기, 스마트 지팡이, 메모리 게임) |
| **일부 변경** 후 가져감 | 14차시 | 입출력 장치만 바꾸면 되는 것 (LED 매트릭스·16x2 LCD → OLED/7세그먼트, 가속도 → 틸트·조이스틱, 네오픽셀 → RGB LED, 앱인벤터 → ESP32 웹서버/BLE, 16x2 게임 → OLED 게임) |
| **부품 구입 후** 가능 | 5차시 | 마퀸·RC카 3주(2WD 섀시 + 모터 드라이버 + 라인 센서), 네오픽셀 무드등 원본 |
| 보드와 무관해 **형식만** 가져감 | 6차시 | AI Intro(ChatGPT 스토리), 중간평가·RFP·스토리 양식, 자율 프로젝트 기획서·회고 |

핵심 발견 세 가지.

1. **세 과정의 핵심 활동은 모두 ESP32로 옮길 수 있다.** 키트에 없는 것은 자석(홀)·적외선 반사 센서·네오픽셀·차량 섀시뿐이고, 각각 틸트·버튼·초음파·RGB LED로 대체하거나 소액 구입으로 해결된다.
2. **아두이노 심화의 "앱" 차시는 ESP32의 WiFi 웹서버가 대신한다.** 키트 튜토리얼(2-2-01~09)에 BLE·웹서버 예제가 이미 있고, 폰 브라우저에서 버튼을 누르거나 값을 보는 페이지로 앱인벤터 앱을 대체하면 설치·페어링 과정이 사라진다. 사이트에는 통신 블록이 아직 없으므로 이것이 가장 큰 신규 개발이다.
3. **기존 10개 챕터에 없는 영역이 드러났다.** 버튼·터치 입력, 수동 부저 멜로디, 마이크·가변저항·조도 같은 아날로그 입력, DHT11, 조이스틱, 키패드, 인터럽트, 게임 프로젝트, 기획서·발표 양식. 이것이 11장 이후의 뼈대가 된다.

## 3. ESP32 수업 제안 — 두 트랙으로 분리 (2026-10-15 수정)

선생님 요청에 따라 **센서 트랙**(모듈 하나씩 익히는 기본기, 1~2차시)과 **교과 융합 트랙**(센서 여러 개를 묶어 교과·SDGs 문제를 푸는 프로젝트, 2~4차시)으로 나눕니다. 융합 챕터는 "먼저 할 센서 챕터"를 적어 관문으로 쓰고, 통신(WiFi 웹서버)은 센서 트랙 끝에, BLE·ESP-NOW는 후순위로 둡니다.

### 3-1. 센서 트랙 (S) — 모듈 하나, 개념 하나

| 번호 | 제목(안) | 원본 | 새 개념 | 부품 |
|---|---|---|---|---|
| S1 | LED 켜기 | 기존 1장 | 디지털 출력, sleep, 반복 | LED |
| S2 | 숨쉬는 LED | 기존 2장 | PWM 듀티 | LED |
| S3 | 신호등 | 기존 3장 | 이름 붙이기, 순서·시간, for | LED 3 |
| S4 | 흐르는 물빛 | 기존 4장 | 리스트 + for | LED 5 |
| S5 | RGB LED | 기존 5장 | 삼원색 섞기, 함수 | RGB LED |
| S6 | 7세그먼트 | 기존 6장 | 74HC595 시프트, 비트 | 튜브 |
| S7 | 작은 선풍기 | 기존 7장 | 두 핀 조합, 함수 이름 | 130 모터 |
| S8 | 버튼과 터치 | AD1 W01 | 디지털 입력, 내장 터치패드, 토글 | 버튼, 호일 |
| S9 | 멜로디 버저 | AD1 W03·W04 | PWM 주파수, 음계 리스트 | 수동 부저 |
| S10 | 박수 스위치와 다이얼 | AD1 W03, MB W05 | 아날로그 입력 0~4095, 임계값, 범위 바꾸기 | 마이크, 가변저항 |
| S11 | 밝기 센서 | AD1 W04 | 조도, 범위별 분기 | 포토레지스터 |
| S12 | 온습도 센서 | AD1 W05 | DHT11, 측정→읽기, 값 없음 처리 | DHT11 |
| S13 | 기울기·사람 감지 | AD1 W05, 키트 PIR | 틸트 스위치, PIR | 틸트, PIR |
| S14 | 초음파 거리 | 기존 10장 1부 | 거리 공식, 도우미 함수 | HC-SR04 |
| S15 | 서보 모터 | 기존 10장·AD1 W07 | 각도 ↔ 신호 길이 | 서보 |
| S16 | 조이스틱 | AD1 W07 | X·Y·버튼, 범위 바꾸기 | 조이스틱 |
| S17 | 키패드와 IR 리모컨 | AD1 W08, 키트 | 키 읽기, 리모컨 값 | 키패드, IR |
| S18 | OLED 화면 | 기존 9장 1부 | 글자·선·네모, 좌표 | OLED |
| S19 | RFID 카드 읽기 | 기존 8장 1부 | 카드 번호 리스트 비교 | RFID |
| S20 | 시간 재기 — 버튼 왕 | AD1 W09 | ticks_ms, 길게·두 번 누르기 판정 | 버튼 |
| S21 | 버튼이 끼어들기 — 인터럽트 | AD1 W10 | Pin.irq, 플래그, 예측 | 버튼, LED |
| S22 | 폰으로 켜는 LED — 웹서버 | AD2 W01, 키트 2-2-05 | WiFi 연결, 요청 경로, 응답 | LED, 폰 |
| S23 | 웹페이지에 센서 값 | AD2 W02, 키트 2-2-07 | 자동 갱신, 값 표시 | 아날로그 센서 |

기존 8·9·10장은 "1부(센서 익히기)"를 S14·S18·S19로 떼어 센서 트랙에 두고, "2부(완성)"는 융합 트랙 F1~F3이 됩니다(진행 기록 호환을 위해 챕터 id 는 유지하고 트랙 태그만 붙이는 방식 권장).

## 5. 버릴 것 / 바꿀 것 / 살 것

**버릴 것(보드 종속):** 마이크로비트 LED 매트릭스 아이콘·스프라이트·게임 블록·가속도 제스처·라디오 그룹·확장보드 핀 이슈; MakeCode "무한반복 여러 개" 병렬 방식(→ 시간 비교); 아두이노 IDE 설치·보드/포트·ZIP 라이브러리·pitches.h·헤더파일 절차; 우노 핀 제한표(인터럽트 0·1번, PWM 핀, tone 간섭, Servo와 analogWrite 충돌); C 문법 주의(세미콜론·#define·sizeof·형변환·'\0'); HC-06 AT 명령·페어링·RX/TX 교차; 코딩어레이 스위치·슬롯 모듈; 앱인벤터 전체(갤러리·QR·ListPicker·Canvas·STT·OrientationSensor·에러코드·aia 제출); 16x2 LCD createChar 트릭; 핀 번호 암기형 평가 문항; 발표자 노트의 잘못 복붙된 문구.

**바꿀 것(값·표현):** 아날로그 0~1023 → 0~4095(임계값 전부 재계산), 5V 기준 전압 환산 → 3.3V, delay → time.sleep, millis → time.ticks_ms, attachInterrupt → Pin.irq, map → 직접 만든 범위 바꾸기 함수(사이트에 블록 추가 권장), tone → PWM 주파수, Serial.print → print(콘솔), 16x2 좌표 → OLED 픽셀(칸×8).

**살 것:**

| 부품 | 쓰는 곳 | 필수도 |
|---|---|---|
| 버튼 모듈 추가(학생당 2~3개) | A/B 버튼 역할(선풍기·무드등·게임) — 키트 수량 확인 | 높음 |

**주의(ESP32 고유):** WiFi를 켜면 ADC2 핀(GPIO 0·2·4·12~15·25~27)은 아날로그 읽기가 안 되므로 통신 챕터의 아날로그 센서는 GPIO32~39에 꽂는다(사이트 검사 규칙으로 경고 권장). 학교 WiFi가 기기 간 통신을 막으면 ESP32 AP 모드로 폰을 직접 붙인다. 불꽃 센서 시험은 라이터 대신 키트 IR 리모컨으로 가능(원본 노트에도 언급). 서보·모터는 외부 전원(키트 배터리 홀더).

## 6. 사이트(ESP32 블록랩)에 새로 필요한 것

현재 사이트(장치 32종, 판단·계산·변수·리스트·흐름 블록, 트랙 10장)에서 위 과정을 담으려면 다음 블록·기능이 필요합니다. 우선순위 순.

1. **입력·시간 블록(11~22장용, 대부분 작은 작업):** 내장 터치패드 읽기, 버튼 인터럽트("버튼이 눌렸을 때" 이벤트 블록, Pin.irq), ms 시간·경과 시간 비교(`calc_ticks` 있음 → "경과 시간 ≥ ?" 편의 블록), 범위 바꾸기(map), 부저 "소리(주파수, 시간)"(있음: 확인), 조이스틱(있음), DHT11(있음), 키패드(있음). 이미 있는 블록이 많아 콘텐츠 작업이 주가 된다.
2. **OLED 게임용:** 점·사각형·비트맵 그리기(선·네모·채운 네모는 있음), 화면 지우기·표시(있음), 글자 크기/반전(선택).
3. **WiFi·웹서버 블록(23~26장용, 가장 큰 신규 개발):** `WiFi 연결(SSID, 비밀번호)`/`AP 모드 시작`, `IP 주소`, `웹서버 시작`, `요청 받기(반복)`, `요청 경로가 ~이면`, `요청 값 꺼내기(이름)`, `웹페이지 응답(제목, 버튼 목록, 값 목록)`, `글 응답`, `자동 새로고침(초)`. 생성 코드는 키트 2-2-05·07·09 예제(`network`·`socket`)와 같은 꼴로 두어 선생님 저장소 코드와 호환.
4. **BLE(선택):** `BLE 시작(이름)`, `연결됐나`, `받은 글이 있으면`, `보내기` — 범용 앱(LightBlue 등) 기준. 웹서버가 더 쉬우므로 후순위.
5. **ESP-NOW(차량·조종기, 선택):** `짝 보드 등록(MAC)`, `보내기`, `받았을 때`.
6. **문자열 블록:** 나누기(split), 포함, 16진수 색 → R·G·B(무드등 웹 색).
7. **검사 규칙:** WiFi 사용 시 ADC2 핀 경고, 인터럽트 핸들러 안에서 sleep 경고.
8. **트랙 형식:** 기획서(무엇·왜·어떻게)·RFP·스토리·발표 체크리스트를 담는 "프로젝트" 단계 유형(설계·성찰 단계 확장), 평가 양식(기능 체크리스트 + 1분 설명).

## 8. 슬라이드를 먼저 만들고 사이트에 반영하는 방식에 대한 의견

**권장: 사이트 챕터(chapter.yaml)를 원본으로 두고, 슬라이드는 거기서 자동으로 만든다.**

- 사이트 챕터에는 슬라이드가 담는 모든 요소가 이미 구조화돼 있다(표지·요약·목표·준비물·배선도·원리·코드·실행 결과·코드 설명·미션·디버깅·설계·성찰·그림 SVG). 슬라이드를 따로 손으로 만들면 같은 내용을 두 번 쓰게 되고, 한쪽을 고치면 다른 쪽이 어긋난다(이번 전환에서도 원본 슬라이드의 발표자 노트·숙제·퀴즈 핀 번호가 본문과 어긋난 곳이 있었다).
- 그래서 "챕터 → pptx 내보내기" 도구를 만들어, 단계마다 슬라이드를 생성한다(제목·장면 그림·상황 글·지금 할 일 / 코드 카드 / 미션·되묻기 / 설계 빈칸 / 성찰 문항). 선생님은 수업 때 슬라이드로 띄우고, 학생은 사이트에서 트랙을 진행한다. 둘의 내용이 항상 같다.
- 검토 흐름은 사이트에서 **초안 상태**(`status: draft`: 교사 모드에서만 보임)로 먼저 만들고, 선생님이 사이트에서 읽어 보며 고친 뒤 공개하면 된다. 슬라이드가 꼭 먼저 필요하면 초안 챕터에서 바로 pptx 를 뽑아 검토용으로 쓸 수 있다.
- 예외: 도입 이야기(AI Intro, SDGs 퓨처비 챌린지)나 교사 시연처럼 사이트 단계에 없는 교사용 장면은 챕터에 `teacherNotes`(교사용 메모·도입 스크립트)를 두고 슬라이드에만 넣는다.

필요 작업 규모: 내보내기 도구(python-pptx, 챕터당 30~50장 자동 생성) 1~2일, 초안 상태·트랙 태그·두 탭 화면 1일, 그다음 S8~S23·F4~F16 콘텐츠.
