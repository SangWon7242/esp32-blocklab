### W01 아두이노로 무엇이든 만들 수 있어요 (86장) + 보충 PNG

**학습 목표(슬라이드)**: "아두이노로 무엇이든 만들 수 있어요." INDEX: 아두이노가 무엇인가요? / IDE 설치하기 & 알아보기 / 디지털, 아두이노 / 입력, 출력 / 우리가 다뤄 볼 아두이노 센서(Coding Array) / 첫 번째 센서 LED와 버튼 / 아두이노 주의사항.

**활동 흐름**
- 도입: MCU 정의("하나의 칩(Chip) 형태로 만든 소형 컴퓨터"), 우노 보드 15개 부위(발표자 노트), 작품 예시(태양광 자동추적기, LED 큐브, 한글 시계, LED 무드등, 애견 급식기, 손소독제 분사기).
- 전개: IDE 설치(arduino.cc) → 메뉴 설명 → setup("시작될 때 한 번만")/loop → 아날로그·디지털, On(1)=HIGH(5V)/Off(0)=LOW(0V) → 보드=두뇌, 센서=오감, 액추에이터=근육·관절 → Coding Array 센서 16종 소개 → LED(D9·10·11) 켜기 → 보드·포트 확인·업로드 → 버튼(D3)/터치(D5)로 D13 LED.
- 미션: "[미션] 초록색, 파란색을 켜봅시다 / RGB를 조합해서 다양한 색"(RGB 디지털 출력 제어 표), "[미션1] 버튼→빨간색, 터치→파란색", "[미션2] 버튼을 누를 때마다 RGB LED의 색상을 바꿔봅시다"(힌트: 전역변수 count), "[미션3] 버튼→0.5초 간격 3번 깜박, 터치→0.3초 간격 10번 깜박", "[미션4] 반복되는 코드를 함수로"(힌트: 매개변수 RGB 값 각각 받기).
- 정리/숙제: "알쏭달쏭 전기퀴즈" 5문항(전기 속도, 감전 대처, 도체, 전깃줄 참새, 정전기) + 아두이노 퀴즈 6~8(setup 1번 실행, pinMode는 전기를 내보내지 않음, delay(1000)=1초, INPUT/OUTPUT).
- 보충 PNG: 키트 v2는 RGB LED(analogWrite 9·10·11), v3는 네오픽셀 1개(`Adafruit_NeoPixel np(1, 9)`, `setPixelColor(0,255,255,255)`, `show()`)로 바뀌었다는 "아두이노 키트 이슈" 안내.

**코드 핵심 → MicroPython**
| Arduino | MicroPython(ESP32) |
|---|---|
| `pinMode(9, OUTPUT)` / `digitalWrite(9, HIGH)` | `led = Pin(n, Pin.OUT)` / `led.value(1)` 또는 `led.on()` |
| `pinMode(3, INPUT)` / `digitalRead(3)` | `btn = Pin(n, Pin.IN, Pin.PULL_DOWN 또는 PULL_UP)` / `btn.value()` (모듈의 눌림 값이 0인지 1인지 먼저 확인) |
| 터치 센서 모듈(D5) | 키트에 없음 → ESP32 내장 정전식 터치 `TouchPad(Pin(터치 가능 핀)).read()` (닿으면 값이 작아짐) |
| `delay(1000)` | `time.sleep(1)` / `time.sleep_ms(1000)` |
| `void loop(){}` | `while True:` |
| 전역 count, 함수 `rgb(r,g,b)` | 전역 변수(`global count`), `def rgb(r, g, b):` |
| 네오픽셀(v3) | `neopixel.NeoPixel(Pin(n), 1)`; `np[0]=(255,255,255)`; `np.write()` — 키트에 없음(구입 시만) |

**사용 부품**: RGB LED, 버튼, 터치, LED. **ESP32 전환 판정: 일부 변경** — LED·RGB·버튼 그대로, 터치 센서 모듈 → ESP32 내장 TouchPad(전선 끝이나 동전 패드), 네오픽셀 → RGB LED 모듈(챕터 5). IDE 설치·보드/포트 선택 부분은 블록랩 "보드 연결"로 대체, 세미콜론·대소문자 주의사항은 "들여쓰기·콜론" 주의로 대체.

**트랙 수업 전환안**: LED 부분은 챕터 1(LED)·5(RGB)와 겹침 → 챕터 1에 "입력" 후속 단계를 붙이거나, 새 챕터 **"버튼과 터치로 켜는 불빛"**(챕터 1 다음 배치)을 만든다.
- 문제 만나기 질문 예: "엘리베이터 버튼은 누르는 순간 불이 들어와요. 보드는 '눌렸다'는 걸 어떻게 알까요?"
- 세 칸 보드: 알아야(버튼 값 0/1, 터치 값) / 정해야(눌렸으면 켠다, 몇 번째 눌림인지) / 움직여야(RGB 색).
- 미션: (1) 버튼=빨강, 터치=파랑(원본 미션1) (2) 누를 때마다 색 바꾸기 — count와 `%`(원본 미션2) (3) 깜박임 횟수·간격을 매개변수로 받는 함수(원본 미션3·4).
- 디버깅 거리: (1) 버튼을 한 번 눌렀는데 색이 여러 번 바뀜(눌림 "순간"이 아니라 "상태"를 셈 — 이전 값 비교 필요) (2) `Pin.IN`에 풀업/풀다운을 안 줘서 값이 떠다님 (3) 함수 안에서 `count += 1` → `UnboundLocalError`(global 누락, 콘솔 Traceback 읽기 연습).

**교과 융합**: 과학(전기 회로, 도체·부도체 — 원본 전기퀴즈 그대로 활용, 감전 대처), 기술가정(전기 안전, 생활 속 입력 장치), 미술(빛의 삼원색 혼합 표 만들기 → 색의 삼원색과 비교), 정보(디지털 0/1, 조건문).
**예상 차시·난이도**: 1~1.5차시(110분 기준), 하. **주의점**: 원본 발표자 노트 코드가 `redPin` 변수를 선언 없이 사용·주석 "13번 LED 켜짐"이 LOW에도 붙는 등 오류가 있음. 퀴즈 8의 "8번핀 버튼"은 W01 본문(버튼 D3)과 다름(이전 키트 잔재). 슬라이드 82~86은 미작성 템플릿.

### W02 시리얼 통신으로 오류를 해결할 수 있어요 (54장)

**학습 목표**: "시리얼 통신으로 오류를 해결할 수 있어요." INDEX: 아두이노의 디버깅은? / 시리얼모니터 알아보기 / LiquidCrystal Display란? / 시리얼모니터로 아두이노에 문자 보내기.

**활동 흐름**
- 도입: 디버깅 정의(나방 일화), "아두이노에서 디버깅은 시리얼 모니터를 통해서 할 수 있습니다."
- 전개: 시리얼 통신(1bit·1byte 직렬), 보드레이트(9600bps가 무난한 이유) → 시리얼 모니터 사용 이유 4가지("센서의 데이터 값을 알고 싶을 때" 등) → `hello, Dlab` 1초 간격 출력 → 버튼 값 출력("BUTTON의 값은:") → LCD 원리(액정·컬러필터) → LiquidCrystal_I2C 라이브러리 ZIP 설치 → "주의! I2C와 A4, A5 핀을 동시에 사용할 수 없습니다"(슬라이드 스위치) → `lcd.init/backlight/print` → 시리얼 입력을 LCD에 쓰기(`Serial.available`, `readString`) → setCursor(칸, 줄).
- 미션: "[미션1] 아래 그림과 같이 LCD에 글자를 출력", "[미션2] LiquidCrystal_I2C.h 메소드를 최소 3개 이상 이용해서 코드를 작성하고 선생님과 친구들에게 코드 설명하기"(display/noDisplay, clear, noCursor, write, blink/noBlink, home).
- 숙제 1~4: 버튼 5번 연속→LED 켬, 터치 5번 연속→끔 / 버튼 4번 & 터치 3번→LED / LCD 어둡게 시작→버튼 시 "System Ready"+LED, 터치 시 끔 / 영상과 같은 프로그램(정답 노트: 버튼·터치로 "A"를 한 칸씩 이동, 0~15 범위 제한).

**코드 핵심 → MicroPython**: `Serial.begin(9600)` → 불필요(USB REPL), `Serial.println(x)` → `print(x)`, `Serial.print(a); Serial.println(b)` → `print(a, b)` 또는 f-string, `Serial.available()/readString()` → `input()`(REPL) — 블록랩 콘솔이 실행 중 표준입력을 받는지 확인 필요, `LiquidCrystal_I2C lcd(0x27,16,2)` → `I2C(scl, sda)` + 디스플레이 드라이버(ssd1306 등), `lcd.setCursor(c, r); lcd.print(s)` → `oled.text(s, c*8, r*8); oled.show()`(8px 글꼴이면 128px 폭 = 16칸이라 16x2 좌표를 그대로 옮길 수 있음), `lcd.clear()` → `oled.fill(0)`, backlight/noBacklight → `oled.poweroff()/poweron()` 또는 `contrast()`. 라이브러리 ZIP 설치 → 블록랩의 라이브러리 자동 업로드.

**사용 부품**: I2C 16x2 LCD, 버튼, 터치. **ESP32 전환 판정: 일부 변경** — 16x2 문자 LCD 없음 → SSD1306 OLED(챕터 9) 또는 KS5020 I2C 128×32 LCD(드라이버 확인 필요). "시리얼 모니터"는 블록랩 콘솔(print + Traceback)로 바로 대응되고 오히려 더 강력함(오류 줄 강조). A4/A5 충돌 같은 우노 고유 주의점은 버림.

**트랙 수업 전환안**: 단독 챕터보다 **모든 챕터 공통의 "콘솔로 오류 찾기" 도입 단계**로 흡수하는 것을 권장(트랙의 디버깅 단계와 동일한 철학). LCD 부분은 챕터 9(OLED 출입화면)의 앞단계 "글자 위치 정하기"로 붙인다.

### W07 아두이노의 센서들 3 (44장)

**학습 목표**: "초음파 센서, 서보모터, 조이스틱 모듈을 사용할 수 있어요." INDEX: 이미 사용되고 있는 센서들? / 초음파 센서 / 서보모터 / 추가모듈-조이스틱 모듈.

**활동 흐름**
- 도입: 산업별 센서(식·약품 온습도, 헬스케어, 스마트폰·자동차, 신재생·해양·항공).
- 초음파(D2 trig, D4 echo, 3~400cm): 340m/s, 10μs 트리거, `delayMicroseconds`, `pulseIn`. 거리 공식 유도 ①~⑥(m/s → cm/us 단위 변환, 왕복이므로 ÷2) → "((340 ×초음파 반환 시간) / 10000) / 2" → LCD에 "Distance [cm]". 발표자 노트: "최대 5분을 주고 해결 못 할 경우 스스로 코드 작성하는 능력 부족".
- 서보(D13, 0~180°, 갈색 GND·빨강 5V·주황 신호, 두 개 이상이면 외부 전원): `servo.attach(핀, 최솟값 544, 최댓값 2400)`, `servo.write(각도)` → "처음 시작하면 서보 모터가 움직이고 이후 가변 저항의 값에 따라 움직이는 코드"(map 0~1023 → 0~180).
- 조이스틱(A1 X, A2 Y, A3 SW, L-Module 스위치, 겹치는 슬롯 모듈 제거): 범위 0~1023, 방향을 FORWARD/BACKWARD/LEFT/RIGHT/CENTER/BUTTON_SW로 정의, `switch`로 `_print("Forward")` 등 LCD+시리얼 출력.
- 숙제: "조이스틱으로 서보모터를 제어해봅시다. 조이스틱 방향이 오른쪽이라면 서보모터가 오른쪽으로…".

**코드 핵심 → MicroPython**
| Arduino | MicroPython |
|---|---|
| `digitalWrite(trig,HIGH); delayMicroseconds(10); digitalWrite(trig,LOW)` | `trig.value(1); time.sleep_us(10); trig.value(0)` |
| `pulseIn(echo, HIGH)` | `machine.time_pulse_us(echo, 1, 30000)`(시간 초과 시 음수 반환) |
| `(float)(340*d)/10000/2` | `340 * d / 10000 / 2` (파이썬 `/`는 자동 실수) |
| `Servo myservo; attach(13); write(90)` | `PWM(Pin(n), freq=50)` + 각도→`duty_u16` 변환 함수(0.5~2.5ms) — 챕터 10의 서보 코드 재사용 |
| `analogRead(A1)` 조이스틱 0~1023 | ADC 0~4095, 기준 250/750 → 약 1000/3000으로 재설정, 중앙값은 2048이 아닐 수 있음 |
| `switch(pos){case …}` | `if/elif` |

**사용 부품**: HC-SR04 초음파, 서보, 가변저항, 조이스틱, LCD. **ESP32 전환 판정: 그대로(값 재보정)** — 모두 KS5020에 있음. 초음파는 5V 전원(챕터 10 지도안: 3.3V면 값이 들쭉날쭉).

**트랙 수업 전환안**
- 초음파 거리 측정·공식 유도는 **챕터 10(초음파 자동문)과 겹침** → 챕터 10의 "원리" 칸에 공식 ①~⑥ 유도를 보강 자료로 붙임.
- 새 챕터 **"다이얼로 움직이는 서보 / 조이스틱 조종기"**: 문제 만나기 "굴착기 기사님은 손잡이를 조금만 밀어도 팔이 조금만 움직여요. 손의 '얼마나'를 각도로 어떻게 바꿀까?" / 미션: (1) 가변저항 → 0~180° (범위 바꾸기 함수 재사용) (2) 조이스틱 방향을 OLED에 글자로(원본) (3) 조이스틱을 기울인 쪽으로 서보가 1°씩 이동, 0~180 넘지 않기(원본 숙제). 디버깅: (1) 조이스틱 가운데인데 "Left"가 계속 뜸(중앙값 측정 안 함 → 데드존) (2) 각도에 180 초과값이 들어가 서보가 떨림 (3) `time_pulse_us`가 -1/-2를 돌려줘 거리가 음수 → 예외 처리.

**교과 융합**: 과학(초음파·가청 주파수 20kHz, 소리의 속력 340m/s, 박쥐·돌고래 반향정위), 수학(거리=속력×시간, 단위 변환, 왕복 ÷2, 식 정리 과정 그대로 수학 활동), 기술가정(로봇 관절, 기계의 각도 제어, 산업 센서), 체육(조이스틱 반응 게임 — 제안).
**예상 차시·난이도**: 서보·가변저항 1차시(중), 조이스틱 1차시(중). **주의점**: 서보 전원(외부 전원 권장), 조이스틱 X·Y 두 개 + 기타 아날로그는 모두 ADC1 핀으로.

### W10 인터럽트와 PWM, LCD 심화 (59장)

**학습 목표**: "PWM은 밝기 제어, 인터럽트는 가로채기?를 할 수 있어요." INDEX: 인터럽트로 가로채는 방법 / PWM으로 LED 밝기와 색 제어하기 / LCD로 색다른 문자 표현하기 / 밝기에 따라, 갑자기 LCD에 다른 문자 쓰기.

**활동 흐름**
- 인터럽트: "마이크로컨트롤러가 프로그램 실행 중 발생하는 특정 예외상황을 먼저 처리하는 기능"(게임하다 코딩 먼저 하는 비유) → `attachInterrupt(인터럽트 번호, 함수, 모드)`, 우노는 0·1번(D2·D3)만, `digitalPinToInterrupt`, 모드 FALLING/RISING/CHANGE/LOW 표 → 실습: D13 LED가 2초마다 깜박이는 동안 버튼 반응이 늦는 코드 → 인터럽트(CHANGE)로 바꿔 즉시 반응 비교(발표자 노트: "인터럽트를 사용하고, 사용하지 않고를 확인").
- PWM: 듀티 사이클 정의, 평균 전압(1.25/2.5/3.75V), 우노 PWM 핀 3·5·6·9·10·11, `analogWrite(핀, 0~255)` → G_LED 밝기 0/25(10%)/128(50%)/255(100%) 1초 간격("analogWrite(G_LED, 0)는 digitalWrite(G_LED, LOW)와 같아요") → **촛불 LED**(R·G 무작위, B=0, delay 0~99 무작위, `random(min,max)`는 max-1까지).
- LCD 심화: 5x8 도트, 하트 배열(B00000…), `lcd.createChar(0~7, 배열)`(8개까지), `lcd.write()` → 하트·"|" 출력, 문자 생성 사이트 → 다음 주 게임 캐릭터(달리기 1·2, 점프, 점프 하단) 그리기.
- "[마무리 미션] 랜덤으로 밝기를 조정해서 다양한 RGB LED 색을 표현하고 LED 색에 따라 LCD 특별한 문자를 출력"(5가지 이상 문자, 색상 범위에 따라 (6,0)~(10,0)에 출력).
- "[추가미션] 마무리 미션 코드에 인터럽트 기능 추가하기 — 인터럽트 버튼을 누르면 모든 문자가 출력"(FALLING, ISR은 `interrupt_Button = true`만, loop에서 처리 후 false).
- 숙제: LCD 문자 출력, "디.게임팩" RFP 작성(제안 개요 / 기획: 게임 선택 → 실행 → 종료 버튼·패배 시 선택 화면 복귀 / 진행계획 1~10주 학습·10주 RFP·11주 구현 / 디버깅 & 유지보수).

**코드 핵심 → MicroPython**
| Arduino | MicroPython |
|---|---|
| `attachInterrupt(digitalPinToInterrupt(3), f, CHANGE)` | `btn.irq(trigger=Pin.IRQ_RISING \| Pin.IRQ_FALLING, handler=f)` — 거의 모든 GPIO 가능(우노의 2개 제한 없음), 핸들러는 `def f(pin):` 형태 |
| 모드 FALLING/RISING/LOW | `Pin.IRQ_FALLING` / `Pin.IRQ_RISING` / ESP32는 `Pin.IRQ_LOW_LEVEL`도 있음 |
| ISR에서 플래그만 세우기 | 동일 패턴 권장(`global pressed; pressed = True`), 핸들러는 짧게 |
| `analogWrite(10, 128)` | `PWM(Pin(n), freq=1000).duty_u16(32768)` (0~255 → ×257), 모든 출력 핀 PWM 가능 |
| `random(0, 256)` | `random.randint(0, 255)` — 끝값 포함 여부가 반대(디버깅 거리) |
| `lcd.createChar(0, heart); lcd.write(byte(0))` | `fb = framebuf.FrameBuffer(bytearray(데이터), 8, 8, framebuf.MONO_HLSB); oled.blit(fb, x, y)` — 8개 제한 없음 |

**사용 부품**: 버튼, RGB LED, LED, LCD. **ESP32 전환 판정: 그대로(인터럽트·PWM) / 일부 변경(LCD 사용자 문자 → OLED 비트맵)**. 인터럽트는 ESP32가 더 자유로움.

**트랙 수업 전환안**
- PWM 밝기 4단계·촛불 LED → **챕터 2(숨쉬는 LED)·5(RGB)와 겹침** → 챕터 2의 추가 미션 "촛불 LED(무작위)"로 붙임. 문제 만나기 "진짜 촛불은 왜 일정하게 빛나지 않을까?"
- 새 챕터 **"버튼이 끼어들기(인터럽트)"**: 문제 만나기 "LED가 2초 동안 쉬고 있는 사이에 누른 버튼은 왜 무시될까?" / 미션: (1) 원본처럼 sleep 2초 깜박임 중 버튼 → 늦게 반응하는 것 관찰(예측 단계에 딱 맞음) (2) `Pin.irq`로 바꿔 즉시 반응 (3) 인터럽트 버튼으로 OLED에 모든 그림 문자 표시(원본 추가미션). 디버깅: (1) 핸들러를 `def f():`로 만들어 `TypeError`(pin 인자 필요) (2) 핸들러에 `handler=f()`처럼 괄호 → 즉시 실행·None 등록 (3) 한 번 눌렀는데 여러 번 호출(바운스 → `ticks_diff`로 200ms 무시).

**교과 융합**: 과학(평균 전압, 잔상 효과로 밝기가 연속적으로 보이는 이유, 불꽃의 깜박임), 수학(듀티비 백분율: 25/255≈10%, 128/255≈50%; 난수와 확률), 미술(픽셀 아트, 2진수로 그림 그리기, RGB 색 혼합), 정보(인터럽트·이벤트, 2진수 B01010).
**예상 차시·난이도**: 인터럽트 1차시(상), PWM·촛불 0.5차시(중), 그림 문자 0.5~1차시(중). **주의점**: 발표자 노트 다수에 W10과 무관한 문구("7주차 코드에는 캐릭터를 1~7번까지…")가 복사돼 있음.

- 스토리(W09 작성분): 놀림받은 엘이를 위해 디콘이가 하이드를 잡으러 벽돌 길을 달림.

**구현 구조(슬라이드 해설)**
- `RunGame_Header.h`(bit.ly 배포, 학생이 채울 빈칸 없음 — "정확한 이해보다 어떤식으로 구성이 되어있는지"): 이미지 번호 1~7(달리기 1·2, 점프, 점프 상·하단, 벽돌 SOLID/RIGHT/LEFT), 디콘이 고정 위치(1번 칸), 상태 번호 0=OFF, 1·2=아래 줄 달리기, 3·10=점프 준비/착지, 4·9=점프 중간, 5~8=점프 상단, 11·12=윗줄 달리기.
- `drawHero(position, terrainUpper, terrainLower, score)`: 위치별 upper/lower 문자 설정 → 그 칸이 벽이면 충돌 → 점수 자릿수 계산 → `'\0'`으로 문자열 끝을 잘라 `lcd.print`로 한 줄씩 빠르게 출력 → 원래 값 복구 → 충돌 여부 반환. `advanceTerrain`(벽 한 칸씩 이동, 삼항연산자 — "정확하게 알 필요 없음").
- 학생 작성부: 그래픽 초기화(createChar ×7, 지면 배열 공백), 인터럽트 함수(2000μs 대기 후 `buttonPushed = true`), setup(시리얼·LCD·"RUN GAME" 3초·인터럽트·초기화), `Run_game()`: static 변수(heroPos, newTerrainType, newTerrainDuration, playing, _blink, distance) → 대기 중엔 Press Start와 캐릭터 깜박임 → 시작 후 새 지면: 타이밍이 0이 되면 빈 지면이면 `random(3)==0`일 때 상단 블록, 아니면 하단 블록·타이밍 2~11, 블록이었으면 빈 지면·타이밍 10~19 → 버튼이 눌렸고 달리는 중이면 점프 시작 → `drawHero`가 충돌 반환 시 게임 종료 → 착지·윗줄 달리기 전환 규칙 → `distance++`. loop: `Run_game()` + 0.1초.

**코드 핵심 → MicroPython**: `static` 변수 → 전역 변수 또는 상태 딕셔너리/클래스, `char terrainUpper[17]` + `'\0'` → 리스트/문자열(끝 표시 불필요), `#define` 상태 번호 → 상수, `attachInterrupt` → `Pin.irq`, `delayMicroseconds(2000)` → `time.sleep_us`는 핸들러에서 피하고 `ticks_ms` 디바운스, `random(3)` → `random.randint(0, 2)`, `lcd.createChar`/`lcd.print` → OLED `blit`/`text`/`fill_rect` + `show()`, `delay(100)` → `time.sleep_ms(100)` 또는 `ticks` 기반 프레임.

**사용 부품**: 버튼, I2C 16x2 LCD. **ESP32 전환 판정: 일부 변경(재작성)** — 문자 LCD 전용 트릭(문자 칸 스프라이트, '\0' 자르기)은 버리고 OLED 128×64 픽셀 게임으로 다시 짜는 것이 더 쉽고 보기 좋음. 128×32 LCD도 2줄 구조라 원본 레이아웃에 가까움(드라이버 확인 필요). 헤더파일 블랙박스 방식은 "코드는 복사, 생각은 직접"·관문 규칙과 충돌 → 작은 함수 단위로 쪼개 학생이 설명할 수 있게.

**트랙 수업 전환안**: 새 챕터 **"달리는 디콘(OLED 점프 게임)"** — 챕터 9(OLED) 이후 최종 프로젝트. 2~3차시로 분할.
- 문제 만나기: "버튼 하나로 하는 게임은 '언제 눌렀는지'를 어떻게 놓치지 않을까? 화면 속 벽돌은 어떻게 움직이는 것처럼 보일까?"
- 세 칸: 알아야(버튼 눌림 플래그, 벽돌 위치들, 캐릭터 높이) / 정해야(점프 중인가, 부딪혔나, 다음 벽돌 언제) / 움직여야(OLED 다시 그리기, 점수, 부저 효과음).
- 단계 분할 제안: (1) 대기 화면 깜박임 + 버튼(irq)으로 시작 (2) 벽돌 리스트를 한 칸씩 왼쪽으로 이동·무작위 생성(타이밍 2~11/10~19 규칙 유지) (3) 점프 상태 번호 + 충돌 판정 + 점수(distance//8) + 게임 오버 → 대기 화면.
- 미션: (1) 벽돌 속도 올리기(점수가 오를수록 프레임 간격 감소) (2) 최고 점수 기억(전원 꺼져도 남기려면 파일 저장 — 심화) (3) 점프·충돌 효과음(멜로디 버저 챕터 재사용).
- 디버깅: (1) 충돌했는데 게임이 안 끝남(벽돌 칸과 캐릭터 칸 비교 위치가 한 칸 어긋남) (2) `random.randint(0, 3)`로 바꿔 윗줄 블록 확률이 달라짐(아두이노 `random(3)`과 끝값 차이) (3) 버튼 한 번에 점프 두 번(바운스/플래그 미초기화).

**교과 융합**: 정보(게임 루프, 상태 기계, 충돌 판정, 난수), 수학(좌표, 확률 1/3, 속력과 프레임 간격), 미술(스프라이트 애니메이션 — 두 장 번갈아 그리기로 달리기 표현, 캐릭터 디자인), 체육(반응 속도·타이밍), 사회·도덕(게임 스토리의 놀림·사과·화해).
**예상 차시·난이도**: 2~3차시, 상. **주의점**: W10 숙제 RFP의 "디랩 게임팩"(게임 선택 메뉴·종료 버튼·선택 화면 복귀)과 W09에서 예고한 "센서 슈팅 게임"은 실제 구현 슬라이드가 없음 — 재설계 시 메뉴 화면은 선택 미션으로.

### 3-2. 버려야 하는 것
- 아두이노 IDE 설치·메뉴 설명, 보드/포트 선택, `.ZIP 라이브러리 추가`, pitches.h·RunGame_Header.h 파일 추가 절차(→ 블록랩 연결·라이브러리 자동 업로드).
- 우노 고유 사항: 인터럽트 0·1번(D2·D3) 제한 표, PWM 핀 3·5·6·9·10·11, `tone()`의 D3·D11 PWM 간섭, Servo 라이브러리의 D9·D10 analogWrite 비활성, A4/A5와 I2C 슬라이드 스위치, 코딩어레이 L-Module 스위치·슬롯 모듈 제거, 5V·0~1023 기준 수치.
- C 문법 주의(세미콜론, `#define`에 `=`·세미콜론 금지, `sizeof` 길이 계산, `(float)` 형변환, `static`, `'\0'` 문자열 끝, `switch`) — 파이썬 대응 개념으로만 짧게.
- 자석(홀) 센서 실습, 적외선 반사 근접 센서 실습(키트에 없음), 16x2 문자 LCD `createChar` 8개 제한·문자 칸 스프라이트 트릭.
- 슬라이드 82~86(W01) 템플릿 잔여, 각 주 발표자 노트의 무관한 복붙 문구("직렬통신은 말 그대로…", "7주차 코드에는 캐릭터를…").
- 핀 번호 암기형 평가 문항(W09 문항 3).

### 3-3. 새로 필요한 부품(선택)
- 필수 아님: 원본의 모든 핵심 활동은 KS5020 + ESP32 내장 기능(TouchPad, 다수 PWM·IRQ 핀)으로 대체 가능.
- 있으면 좋은 것: 리드 스위치 또는 홀 센서 모듈(W05 자석·W06 게임 시작 원본 재현), 적외선 반사 센서(TCRT5000 등, W06 흑백 구분·라인 감지), 네오픽셀 1개 또는 스트립(W01 보충 PNG의 v3 코드 재현, MicroPython `neopixel` 내장), 서보 외부 전원(5V 배터리 홀더 — KS5020 배터리 홀더 활용 가능), 키패드 사용 시 외부 풀업 저항(GPIO34~39 사용 때).
- 확인 필요: KS5020의 "I2C LCD 128×32" 드라이버(블록랩은 현재 ssd1306 OLED 드라이버만 보유).
