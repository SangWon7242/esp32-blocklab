# 아두이노 심화(DM-AD-2) 과정 분석 — ESP32 MicroPython 재설계용

원본: `slides_txt/ad2/` 10개 파일(슬라이드 본문 + 발표자 노트, 총 715장). 아래 인용은 슬라이드 원문이다.
전제: 기존 수업은 아두이노 UNO + 코딩어레이(센서 일체형 쉴드) + HC-06 블루투스 모듈 + MIT App Inventor 앱. 슬라이드 7("이번학기 우리는 아두이노와 앱인벤터를 연동해서 프로젝트를 진행할거에요.")처럼 매 차시가 "아두이노 코드 + 앱인벤터 앱" 쌍으로 구성된다.

공통 패턴(1~9주차 거의 동일):
- 도입: 목표 슬라이드("Big idea", 예: "재난을 감지해서 앱으로도 알려줄 수 있어요.") → 생활 사례/영상 → 기획서(항목 | 내용 표: 프로젝트 명, 기획 개요, 게임 방법/감지 범위).
- 전개: 앱인벤터 갤러리 "MK-AD-2" 검색 → 리믹스 → 디자이너 화면 확인 → 블록 코딩(①센서값처리 procedure ②블루투스 수신 변수 ③Clock.Timer로 수신·split ④버튼 → 문자 전송) → 쉬는 시간 → 아두이노 코드(시리얼로 "값,값,값," 전송 또는 문자 1개 수신).
- 정리: "BT Module PIN Select Switch" 확인(업로드 때 내림, 사용 때 올림) → 폰 블루투스 페어링 → "scan QR code" → 실습 영상 → [미션] → 숙제.
- 통신 규약: 아두이노→앱은 `Serial.print(값); Serial.print(',')` 형태의 CSV 또는 1글자 상태 코드('f','t','b','w','n'), 앱→아두이노는 1글자 명령('1','0','e','s','c','u'...) 또는 바이트 배열.

## 2. 차시별 분석

### W01. 아두이노로 무엇이든 만들 수 있어요 (53장)

**학습 목표**: "아두이노로 무엇이든 만들 수 있어요." 스마트폰과 아두이노를 블루투스로 연결하고 앱으로 LED를 켜고 끈다.

**활동 흐름**
- 도입: 학생 작품 사례(발표자 노트: 장애물 감지 그립톡 최우수, 비말 차단 텀블러 우수, 콘센트 먼지 클리너 우수, 택배분실방지 스마트 매트 입상 — "대한민국 발명대회 참여 作"), 태양광 자동추적기·LED 큐브·한글 시계·애견 급식기 등.
- 전개 1(연결 준비): 코딩어레이 5·8번 핀 센서 모듈 탈착 → "BT module PIN Select Switch" 내림 → HC-06 RX/TX/GND/VCC 연결. TX(Transmit)/RX(Receive) 개념.
- 전개 2(설정): SoftwareSerial 중계 코드 업로드 → 시리얼 모니터에서 `AT` → "OK", `AT+NAME…` → "OKsetname", `AT+PIN…` → "OKsetPIN". 이유: "블루투스 초기설정이 모두 같기 때문에 다른친구들과 섞이지 않도록 이름과 PIN번호를 변경합니다."
- 전개 3(페어링): 폰 블루투스 설정에서 이름 찾기 → PIN 입력.
- 전개 4(앱): AD2_w01_Bluetooth(ListPicker "블루투스 연결", Button "블루투스 끊기", BluetoothClient) → 다른 이름 저장 AD2_w01_LEDApp(ON/OFF 버튼이 '1'/'0' 전송).
- 정리/미션: "스마트폰 앱에 3개의 버튼" — '2' 1번 깜빡, '3' 2번, '4' 3번(1초 간격).
- 숙제: LED ON/OFF에 따라 I2C LCD에 "LED ON"/"LED OFF" 출력.

**코드 핵심과 ESP32 대응**
- 아두이노: `if(Serial.available()>0){ char data=Serial.read(); if(data=='1') digitalWrite(LED,HIGH); else digitalWrite(LED,LOW); }`
- 앱인벤터: ListPicker.BeforePicking에 AddressesAndNames, AfterPicking에 Connect, 버튼에서 `BluetoothClient.SendText "1"`.
- ESP32 대응
  - WiFi 웹서버(권장): `network.WLAN(STA_IF)` 접속 → IP 출력 → `socket` 서버가 `GET /on`, `GET /off` 경로를 보고 LED 제어 → ON/OFF 버튼이 있는 HTML 응답. 키트 튜토리얼 "2-2-05_IoT_Control_LED_Via_Web_Server"와 동일 구조(폰 브라우저에 IP 입력).
  - BLE UART(대안): `bluetooth` 모듈 BLE 주변기기 + LightBlue 앱에서 "1"/"0" Write(키트 "2-2-01_IoT_Bluetooth_Control_LED"). 
  - AT 명령 이름 변경 → 코드 안에서 BLE 이름/웹 AP 이름을 학생별로 지정(같은 문제 의식 유지: "섞이지 않게").
  - 숙제 LCD 16x2 → I2C LCD 128×32 또는 SSD1306 OLED에 "LED ON/OFF".

**사용 부품**: LED, (숙제) LCD.

**ESP32 전환 판정: 일부 변경** — 통신 주제와 LED 제어는 그대로, HC-06 설정·스위치·페어링·앱인벤터 제작은 제거하고 웹 페이지 또는 BLE 앱으로 대체.
- 필요한 새 블록: `WiFi 연결(SSID, 비밀번호)`, `IP 주소 출력`, `웹서버 시작(포트 80)`, `요청 경로가 ~이면`, `웹페이지 응답(버튼 목록)`. BLE 선택 시 `BLE 시작(이름)`, `BLE 받은 문자`, `BLE 보내기`.

**트랙 수업 전환안 — 새 챕터 "11. 폰으로 켜는 LED(웹서버 입문)"**
- 문제 만나기: "선 없이 내 폰으로 교실 반대편의 LED를 켤 수 있을까? 폰과 보드는 무엇으로 말을 주고받을까?"
- 조건 분석(세 칸): 입력=웹 버튼 요청(/on, /off) / 처리=경로 비교 / 출력=LED + 상태 문구가 담긴 페이지.
- 예측: "/on 주소를 직접 입력하면 버튼을 안 눌러도 켜질까?"
- 미션: 원본 미션 그대로 — 버튼 3개로 1·2·3번 깜빡이기(/b1, /b2, /b3).
- 디버깅 거리: 폰과 보드가 다른 WiFi에 접속(키트 주의 문구: 같은 LAN이어야 함), IP 오타, 응답 후 `cl.close()` 누락으로 페이지 무한 로딩, '/on'과 '/' 비교 순서 오류(`'/o' in request` 같은 포함 비교 함정).
- 설계: LED 상태를 페이지에 "LED state: ON/OFF"로 표시.
- 성찰: 블루투스(1:1 페어링)와 WiFi(같은 네트워크 + 주소) 차이.

**교과 융합**
- 정보: 통신의 송신/수신(TX/RX), 클라이언트-서버, URL 경로 — 슬라이드 "모든 통신을 위해서 보내고 받는 부분이 필요합니다." 활용.
- 사회/실과: 발명대회 작품 사례 감상, "생활 속 불편 찾기".
- 활동: 교실 안에서 한 학생은 브라우저(손님), 한 학생은 보드(가게) 역할극으로 요청-응답 체험.

**예상 차시·난이도**: 2차시(연결 1 + 미션 1), 중. WiFi 접속이 첫 관문.

**주의점**
- 학교 WiFi가 기기 간 통신을 막는 경우가 많음 → ESP32 AP 모드(`network.AP_IF`, 학생별 SSID)로 폰이 보드에 직접 접속하는 축소안 준비.
- 축소안(폰 없이): 사이트 콘솔/REPL에서 '1','0' 입력으로 LED 제어(원본 W08 "시리얼 모니터로 값을 보내" 방식과 동일). 사이트 콘솔에서 보드로 입력을 보낼 수 있는지 확인 필요.
- 주의: BLE는 iOS·안드로이드 모두 별도 앱(LightBlue 등) 설치 필요, 웹 방식은 설치 불필요.

### W02. 아두이노 센서 값 확인 앱 (64장)

**학습 목표**: "아두이노의 모든 센서를 앱으로 확인할 수 있어요."

**활동 흐름**
- 도입: 사람의 오감 ↔ 센서, 보드=두뇌 / 센서=오감 / 액추에이터=근육·관절. 물리적 정보 → 디지털/아날로그 신호.
- 전개 1: 코딩어레이 센서 소개(Analog Wing/Digital Wing), 오늘 사용 7개: 마이크, 가변저항, 조도, 초음파, 적외선 근접, 기울기, 온습도.
- 전개 2: `delay()`는 "아두이노가 아예 멈춰서 다른 코드가 동작하지 않아요" → `millis()`로 `now - past >= 3000` 패턴. flag 0/1로 LCD 화면을 3초/5초마다 번갈아 출력(1화면: 가변저항·조도·초음파 / 2화면: 적외선·기울기·온습도·사운드). 출력 함수 일부를 학생이 완성.
- 전개 3(앱): 갤러리 리믹스 → 센서값처리 procedure: 값이 공백이 아니면 임계값으로 Label 배경 흰색/빨간색(적외선·기울기 0이면 흰색, 온습도 25 이하, 사운드·가변저항·조도 500 이하, 초음파 10 이하면 흰색). Clock.Timer에서 수신 문자열을 ","로 split → 리스트 → procedure 호출 → 초기화.
- 전개 4(아두이노): LCD 코드를 수정해 7개 값을 `값,` 형태로 시리얼 전송, `get_cm()`만 남김.
- 미션: "3번 핀에 연결된 버튼의 눌림 상태를 앱으로 확인해봅시다."
- 숙제: 적외선 감지 시 "감지됐습니다." 알림 앱. 추가 숙제: "알림이 연속으로 울리지 않도록 해보세요."

**코드 핵심과 ESP32 대응**
- millis → `time.ticks_ms()`, `time.ticks_diff(now, past) >= 3000`.
- LCD 2화면 전환 → OLED 128×32(4줄) 또는 LCD 128×32에 페이지 전환 — 화면이 작아 원본의 "flag로 화면 바꾸기"가 오히려 자연스럽다.
- CSV 전송 + 앱 split → 웹: (a) 서버가 매 요청마다 값을 읽어 HTML 표로 응답하고 `<meta http-equiv="refresh" content="2">`로 자동 갱신(블록화 쉬움), (b) `/data` 경로가 "값,값,…" 텍스트를 주고 페이지 JS가 1초마다 fetch(앱의 Clock.Timer + split과 1:1 대응, 고급). 임계값 색칠은 MicroPython에서 `if 값 <= 기준: 색='white'`로 HTML에 넣으면 앱 procedure와 같은 사고.
- 키트 튜토리얼 2-2-07(LM35 웹), 2-2-08(DHT11 웹)은 "새로고침 버튼을 눌러야 갱신" 구조 → 자동 갱신은 새 내용.

**사용 센서 대응**: 마이크→소리 센서, 가변저항→포텐셔미터, 조도→포토레지스터, DHT11→DHT11, 기울기→틸트 스위치, 초음파→HC-SR04, 적외선 근접 센서→키트에 없음(PIR 또는 버튼으로 대체).

**ESP32 전환 판정: 일부 변경** — 센서 7개 중 6개 그대로. 적외선 근접만 대체. 앱 → 자동 갱신 웹 대시보드.

### W04. 재난 감지 앱 만들기 (79장)

**학습 목표**: "재난을 감지해서 앱으로도 알려줄 수 있어요."

**활동 흐름**
- 도입: 화재 실험·지진·각종 재난 영상 시청 → 센서·인공지능 재난 예방, 긴급상황 감지·대피로 안내, 2차 피해 예방 사례.

- 앱: 센서값처리(state 매개변수) — 'f' 포함이면 Button_fire 배경·Label_state·화재 알림, 't'면 지진, 'b'면 "현재 위치는 ~~입니다.", 아니면 모두 원래색 "미감지". Button_exit → 'e' 전송.

- 미션: 앱 화면 디자인, 터치 센서로 "이동해야할 방향" 알림 추가, 적외선/초음파 물체 감지 시 현재 위치 알림.
- 숙제: C언어 복습 2문항(요일 학교 가는 날 "oh my god"/"enjoy", 별 찍기).

**코드 핵심과 ESP32 대응**
- 아두이노 if-else 사슬로 상태 문자 결정 → MicroPython 동일(`if flame >= 기준 and temp >= 27: state='f'`). 원본은 우선순위가 화재>지진>버튼(else if)이라는 점이 좋은 사고 거리.
- 앱 상태 표시·알림 → 웹 페이지가 `state`에 따라 배경색·문구를 바꿔 응답(자동 새로고침). "출구를 알려줘" 버튼 → `GET /exit` → 부저 PWM.
- 동시에 보드 자체 경보(부저·LED·OLED "화재!")를 넣으면 폰 없이도 완결.
- tone → `PWM(Pin(n), freq=…)`, noTone → `duty(0)` 또는 `deinit()`.

**사용 부품**: 불꽃 센서·DHT11(또는 LM35·서미스터)·기울기·버튼·수동 부저 모두 키트에 있음. 터치 센서 없음(미션 → 버튼/조이스틱으로).

**ESP32 전환 판정: 그대로(통신 부분만 웹으로)** — 키트로 100% 구현 가능. 
- 새 블록: `상태 문구를 웹 페이지에 표시`, `웹 버튼 → 경로`, `부저 소리(주파수)`, `부저 끄기`.

### W05. 랜덤 망치 게임 만들기 (85장)

**학습 목표**: "물체를 감지하면 랜덤하게 망치가 움직여요."

**활동 흐름**

  - 미션: 'A' 시퀀스 → "약풍 1초 → 정지 0.5초 → 강풍 2초 …" 시퀀스.

- 구매 시: "18. 라인을 따라가는 자동차" — 원본 그대로.
  - 문제 만나기: "사람이 조종하지 않아도 길을 따라가는 차는 어떻게 길을 볼까?"

### W09. 블루투스 RC카 프로젝트2 (84장)

**학습 목표**: "블루투스 RC카를 업그레이드 할 수 있어요!"

**활동 흐름**
- 앱(갤러리 리믹스) Screen1: 블루투스 에러 처리 — "에러코드 507번 일 때, 블루투스 전원을 확인하는 메시지", 516번은 연결 상태 확인, 그 외 에러코드·내용 표시, 에러 시 연결 해제. 모드1 시작 '1'+'s', 종료 '1'+'e'. Button_mode2/3 → 연결 끊고 다른 스크린으로(컴포넌트 Ctrl+C/V로 복사, 블록도 함께 복사).

### 3-2. 버려야 하는 것
- HC-06 관련: SoftwareSerial 중계 코드, AT/AT+NAME/AT+PIN 설정, 폰 블루투스 페어링·PIN 입력, RX/TX 교차 연결 주의.
- 코딩어레이 관련: 5·8번 핀 센서 모듈 탈착, "BT Module PIN Select Switch" 업로드 때 내리고 사용 때 올리기, I2C와 A4·A5 슬라이드 스위치.
- 앱인벤터 전부: 갤러리 "MK-AD-2" 리믹스, QR 코드 연결, ListPicker/BluetoothClient, Clock.Timer 수신, Canvas/ImageSprite 게임, Notifier, SpeechRecognizer(STT), OrientationSensor, 에러코드 507/516, 멀티 스크린 복사·배낭, ImagePicker, aia 제출.
- UNO 고유 지식: LiquidCrystal_I2C ZIP 설치, RunGame_Header.h, PWM 핀 3/5/6/9/10/11 제한, tone()의 3·11번 PWM 간섭, Servo 라이브러리의 9·10번 PWM 비활성, `unsigned long` millis 오버플로(49.7일).
- C언어 복습 숙제(W04, W05) → Python 조건문·함수 복습으로 교체.
- 16x2 LCD 커스텀 문자 게임 → OLED.

### 3-3. 새로 필요한 부품
- RC카(선택): 2WD 섀시(기어모터 2·바퀴·볼 캐스터), 모터 드라이버(L9110S 또는 TB6612FNG), 라인 센서 TCRT5000 ×2, 모터용 배터리(AA 홀더 또는 18650) — 모터 전원 분리·GND 공통. 무선 주행 시 ESP32용 보조배터리.
- 무드등(선택): WS2812 네오픽셀 링/스틱(MicroPython `neopixel` 내장 지원), 케이스(MDF/아크릴 또는 종이컵·한지 대체), 형광펜.
- 기타: 적외선 근접/반사 센서(원본 W02·W03 점프 입력 — 없으면 버튼·PIR·초음파로 대체), 터치 센서(W03·W04 미션 — 없으면 버튼), 두 번째 ESP32(ESP-NOW 조종기, 선택), 랜덤 망치용 종이컵·나무젓가락, 서보용 5V 외부 전원.
- 네트워크: 학생 기기 간 통신이 되는 WiFi(학교망이 막으면 ESP32 AP 모드 사용).

### 3-4. 사이트(ESP32 블록랩)에 새로 필요한 블록
- WiFi: `WiFi 연결(SSID, 비밀번호)`, `연결될 때까지 기다리기`, `IP 주소`, `AP 모드 시작(이름, 비밀번호)`.
- 웹서버: `웹서버 시작(포트)`, `요청 받기(반복)`, `요청 경로가 ~이면`, `요청에서 값 꺼내기(이름)`(쿼리스트링), `웹페이지 응답(제목, 버튼 목록, 값 목록)`, `텍스트 응답`(/data용), `자동 새로고침(초)`, `색칠된 상태 칸`(값과 기준으로 색), `연결 닫기`(내부 처리 권장).
- BLE(선택): `BLE 시작(이름)`, `BLE 연결됐나?`, `BLE 받은 글자가 있으면`, `BLE 보내기(문자열)`(LightBlue 등 범용 앱 기준).
- 문자열/자료: `문자열 나누기(구분자)`, `n번째 값`, `글자 포함?`, `16진수 색 → R,G,B`.
- 시간/수학: `ms 시간`, `경과 시간(ms) ≥ ?`, `랜덤 정수(a~b)`, `범위 바꾸기(map)`.
- 장치: `부저 소리(주파수, 시간)`/`부저 끄기`, `서보 각도`(기존 확인), `초음파 거리`(기존 10장), `DHT11 온도/습도`, `불꽃/조도/소리 아날로그 읽기(0~4095)`, `조이스틱 X/Y/버튼`, `RGB LED 색(R,G,B, 밝기)`, `모터 방향·속도(PWM)`, (선택) `네오픽셀 색/표시`, `ESP-NOW 보내기/받기`.
- OLED 게임용(W03): `점/사각형/비트맵 그리기`, `화면 지우기·표시`, `핀 인터럽트(눌렸을 때)`.
- 웹 블록 설계 주의: ADC2 핀은 WiFi와 동시 사용 불가 → 아날로그 블록의 핀 선택지를 ADC1(GPIO32~39)로 안내하는 경고 필요.

### 3-6. 제안 챕터 번호(기존 1~10 이후)
11 폰으로 켜는 LED(웹서버) → 12 우리 반 센서 상황판 → 13 재난 알리미 → 14 복불복 랜덤 망치 → 15 감성 스마트 무드등 → 16 OLED 달리기 게임 → 17 원격 팬·PWM(키트) → (구매 시) 18 라인 자동차, 19 3모드 RC카 → 캡스톤(기획서·스토리·발표). 비밀번호 자물쇠(키패드+서보)는 W06 평가 미션으로 8장 RFID 다음 보충 미션에 배치 가능.
