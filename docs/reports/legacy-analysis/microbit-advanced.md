# 마이크로비트 심화(DS-MB-2) 11주 과정 분석 — ESP32 MicroPython 재구성용

- 분석 대상: `slides_txt/mb2/` 텍스트 16개(덱 13종 + 수정본 3개). 슬라이드 본문과 발표자 노트만 근거로 삼았고, 그림(블록 스크린샷)은 텍스트로 추출되지 않아 블록 세부는 슬라이드 문장으로만 확인했다.
- 수업 대상: AI Intro 프롬프트에 "초등학교 2~4학년 학생들과 함께"라고 적혀 있음(W04·W07 AI Intro).
- 수정본 비교(결론: 수정본 기준으로 분석, 내용 차이 거의 없음)
  - W07 `_수정본(250716)`: 텍스트 동일. 44번 슬라이드 "(왼쪽(left)/오른쪽(right)/모두(all))" → "전체(all)"로 바뀌고 설명 줄 순서만 달라짐, 45번 그림 5→4개. 블록 스크린샷 교체로 보임.
  - W08 `_수정본(250717)`: 텍스트와 그림 수 모두 동일. 개체 순서만 바뀜(그림 위치·교체 수준).
  - W09 `_수정본(250717)`: 텍스트 동일. 50번 "완성코드" 그림 1→2개(완성 코드를 두 장으로 나눈 것으로 보임).
- 모든 프로젝트 덱의 공통 구조: **퓨처비 챌린지(SDGs) 도입 → 목표 → 기획(기능표·모드표·변수표) → 테스트 H/W → 단계별 코드 → 메이킹 → 테스트/체크리스트 → 마무리**. 이미 블록랩 트랙(문제 만나기 → 조건 분석 → … → 성찰)과 흐름이 비슷해 옮기기 쉽다.

## 2. 차시별 분석

### W01 센서 사용법 (47장)

- **학습 목표(원문)**: "여러가지 센서의 용도와 작동법을 알아보아요." 표지 노트: "마퀸은 7주차부터 사용합니다."
- **활동 흐름**
  - 도입: 새 프로젝트 `w1_센서사용법`. "설명하는 내용을 센서 카드에 적어주세요(이론 + 코드에 대한 설명)", 센서마다 소개 후 바로 마이크로비트로 테스트.
  - 전개(센서 6종, 각 "스스로 코딩을 완성해 봅시다")
    1. 서보: 0~180도, A버튼 → 0도, 2초, 180도, 2초. 퀴즈 "'일시중지 2000(ms)' 블록을 사용하는 이유는?" → "모터가 돌아갈 시간을 주기 위해서".
    2. DC모터: 시작 0, A=1023(최대), B=500, A+B=0. "0~1023 사이의 값을 설정해서 모터의 속도를 조절". 노트: v2에서는 0번 핀이 아니라 16번(5V) 핀을 쓰고 배터리케이스 연결, VCC 스위치 5V 확인.
    3. 버저: 0번 핀 전용. 음 출력/계속 출력/쉼/멜로디 블록. 노트: "각자 5초 이내 길이의 음악을 만들 수 있도록".
    4. 가변저항: 0~1023 아날로그 입력, 음악 블록과 결합(돌리면 음이 변함).
    5. 초음파: 송신부/수신부, 2~400cm, "측정되는 거리가 아주 정확하지는 않습니다". 0번 핀(1핀형)에서 cm 측정 → LED에 출력.
    6. 링 LED: 8구 RGB, 객체 생성, 모두 같은 색(무지개+흰·검·남), 무지개 → 한 칸씩 밀기 → 보여주기 → 200ms ×8. 안전: "불빛이 강하니 눈으로 LED를 오래 보지 마세요", 포스트잇·종이 커버.
  - 정리: "다음주부터 센서를 활용하여 작품을 만들 예정입니다. 센서 카드를 꼭 들고 다니세요".
- **코드 핵심**: 버튼 이벤트, 일시중지, 아날로그 쓰기/읽기, 확장(초음파·네오픽셀) 블록, 반복 8회.
- **센서·부품**: 서보, DC모터, 버저, 가변저항, 초음파, 링 LED, 확장보드, 배터리박스.
- **ESP32 전환 판정: 일부 변경**
  - 서보·DC모터(130 팬 모듈)·버저(수동)·가변저항·초음파 HC-SR04는 키트에 있음. 링 LED는 없음 → RGB LED로 대체하거나 WS2812 링 구입(MicroPython 내장 `neopixel` 모듈 사용 가능).
  - 차이: ESP32 ADC는 0~4095(12비트), PWM duty는 0~1023이라 DC모터 0~1023 값은 그대로 이어진다. HC-SR04는 Trig/Echo 2핀. 버튼 A/B는 버튼 모듈 필요. MakeCode 음악 블록(박자·템포)이 없으므로 음 주파수표 + 함수로 직접 만들어야 한다.
- **KS5020 모듈·핀 제안**(키트 튜토리얼·기존 수업 코드 기준): 서보 IO4, 팬 IN+ IO13 / IN- IO12, 수동 버저 IO13(단독 테스트 시)·조합 시 IO26, 가변저항 ADC IO36, 초음파 Trig IO13 / Echo IO12, RGB LED R27·G25·B26, 버튼 IO14(PULL_UP).
- **트랙 수업 전환안**: 별도 챌린지로 두기보다 "센서 카드" 활동을 각 챕터의 **원리** 단에 흡수. 서보·초음파는 이미 8·10장, DC모터는 7장, RGB는 5장에 있음. 새로 필요한 것은 "부저 연주"와 "가변저항" 두 짧은 챕터(또는 기존 2장 숨쉬는 LED에 가변저항으로 밝기 조절 확장).
  - 문제 만나기 예시: "손잡이를 돌리면 소리가 높아지는 악기를 만들 수 있을까?"
  - 미션: 5초짜리 멜로디 만들기 / 가변저항으로 음 높이 바꾸기 / 버튼 두 개로 팬 세기 두 단계.
  - 디버깅: 서보 0→180 사이에 기다림이 없어 움직이지 않는 코드("일시중지를 쓰는 이유" 퀴즈를 그대로 디버깅 거리로) / ADC 최댓값을 1023으로 착각해 범위 조건이 안 맞는 코드.
- **교과 융합**: 과학(소리의 성질: 진동과 높낮이, 전기 회로), 음악(가락 만들기, 계이름과 주파수), 실과(생활 속 센서 찾기). 활동: 센서 카드를 "생활 속 어디에 쓰이나" 조사 카드로 확장 / 가변저항 음높이로 간단한 계이름 연주.
- **예상**: 110분 1회(센서 3종씩 2회로 나눠도 됨), 난이도 하.
- **주의**: 모터·서보는 외부 전원(배터리 홀더) 사용, 링 LED 사용 시 눈부심, ESP32 GPIO 34~39는 입력 전용.

### W02 시각장애인을 위한 스마트 지팡이 (57장)

- **학습 목표(원문)**: "여러가지 센서를 이용하여 스마트 지팡이를 제작해 보고 함수를 사용해 코딩할 수 있어요."
- **활동 흐름**
  - 도입: 퓨처비 챌린지 [10. 불평등 해소] → 소득·건강·성별·교육 불평등, 장애인 차별 → "필요 보조 기기 지원" → "시각장애인을 위한 스마트 지팡이를 만들어봅시다". 흰 지팡이 영상(노트: "장난으로 만들지 말고 진지하게 대할 수 있도록", '흰' 지팡이인 이유 토의), 완성 지팡이 시연 영상.
  - 기획: 기능 3가지 — 초음파 센서와 버저로 물체 감지 / LED로 밤에도 다른 사람이 확인 / 가속도 센서로 지팡이를 놓쳤을 때 소리 알람. "각각의 기능을 함수로 작성". 함수 복습("코드가 길거나 복잡할 때, 같은 내용이 여러 번 반복될 때").
  - 전개
    1. 물체 감지: 변수 "거리" 초기값 30, 초음파 값 저장. 거리 < 30이면 소리, 아니면 무음. 거리에 따라 박자가 다름 — 멀다(30)→템포 20, 가깝다(0)→템포 160, "비례변환 사용".
    2. 빛 감지: 빛 센서 0~255, 10보다 작으면 LED 깜빡이기(노트: 교실 밝기에 맞게 값 조절).
    3. 놓쳤을 때: 가속도 y < 50이면 템포 160, '높은 미' 1/4박, 1/4박 쉬기.
    - 노트: 어두울 때 LED 깜빡임 시간 때문에 같은 거리에서도 소리 주기가 달라질 수 있음(한 루프에 여러 기능을 넣은 결과).
  - 메이킹: 박스지 도안, 막대 3개, 접기·테이프(10단계, 유튜브 영상).
  - 정리: 테스트 3종(물체 감지·빛 감지·놓쳤을 때), "모든 함수가 기획한 대로 동작하나요?"
- **코드 핵심**: 함수 3개 + 무한반복에서 호출, 변수, if/else, 비례변환(map), 음악 템포.
- **센서·부품**: 초음파(P1), 버저(P0), 내장 빛 센서, 내장 LED 매트릭스, 내장 가속도, 배터리박스.
- **ESP32 전환 판정: 일부 변경(키트로 완전 구현 가능)**
  - 내장 빛 센서 → 포토레지스터(ADC 0~4095, 기준값 다시 찾기).
  - LED 매트릭스 깜빡임 → LED 모듈.
  - 가속도 y값 → **기울기(틸트) 스위치**: 지팡이가 누우면 값이 바뀜. 오히려 원리가 단순해 초등에 적합.
  - 템포 비례변환 → MicroPython에 map이 없으므로 직접 함수(`def 비례변환(값, 입력최소, 입력최대, 출력최소, 출력최대)`) 작성, 또는 "삐 간격(ms) = 거리 × 10" 같은 단순 비례식으로.
- **모듈·핀 제안**: 초음파 Trig 13 / Echo 12(10장과 같게), 수동 버저 IO26, LED IO27, 포토레지스터 ADC IO36, 틸트 스위치 IO14. 외부 전원(배터리 홀더)로 들고 다니게.
- **트랙 수업 전환안**: 10장(초음파 자동문) 뒤 **새 챕터 "스마트 지팡이"**. 함수 나누기를 처음 본격 다루는 챕터로 적합.
  - 문제 만나기: "앞이 보이지 않는 친구가 길에서 기둥에 부딪히지 않게 하려면 지팡이가 무엇을 알려줘야 할까?"
  - 조건 분석(세 칸): 가까움(30cm 미만)/어두움(빛 값 기준 미만)/누움(틸트 켜짐) → 각각 소리 빠르기/LED 깜빡/경보음.
  - 미션: 가까울수록 삐 소리가 빨라지게 / 어두우면 LED 깜빡 / 지팡이를 눕히면 경보.
  - 디버깅: `if 거리 < 30` 대신 `> 30`으로 반대로 울리는 코드 / 함수를 만들어 놓고 반복문에서 호출하지 않은 코드 / 빛 기준값을 micro:bit 값(10)으로 둬 늘 켜지는 코드.

"센서 사이에 있는 검정색 선을 감지하여". 규칙: 둘 다 흰색 → 직진, 왼쪽 검정·오른쪽 흰색 → 좌회전, 왼쪽 흰색·오른쪽 검정 → 우회전, 둘 다 검정 → 정지. else-if 사슬로 완성.
  - 정리: 완성 코드.
- **코드 핵심**: for index 반복, 리스트, 두 센서 값 조합의 다중 조건(4가지 경우).
- **센서·부품**: 마퀸 라인트래킹 센서 2, 모터 2, RGB 4.
- **ESP32 전환 판정: 불가(라인 센서 + 차량 구입 시 가능)**
  - 키트에 라인트래킹(적외선 반사) 센서 없음 → TCRT5000 등 디지털 출력 모듈 2개 + 2WD 차량 필요.
  - 키트로 살릴 수 있는 부분: ① RGB 색 리스트 반복(5장 RGB + 리스트 미션) ② **반사 원리 실험**: LED + 포토레지스터를 나란히 두고 흰 종이/검은 종이를 대어 값 차이 확인(적외선 대신 가시광으로 같은 원리) ③ 두 센서 4가지 경우 표는 버튼 2개로 "가상 라인트레이서"(LED로 직진/좌/우/정지 표시)로 조건 분석 연습.
- **모듈·핀 제안(구입 시)**: 라인 센서 왼쪽 IO34, 오른쪽 IO35(입력 전용 핀에 적합), 모터는 W07 배치와 동일.
- **트랙 수업 전환안**: 차량 단원 두 번째 챕터 "라인 따라 가는 물류 로봇". 차량이 없으면 "빛 반사 탐지기"(포토레지스터) 짧은 챕터로.
  - 문제 만나기: "창고 바닥의 검은 선만 따라 물건을 나르는 로봇은 어떻게 길을 알까?"
  - 조건 분석: 왼쪽 센서 / 오른쪽 센서 / 동작(4가지 경우 표).
  - 미션: 센서 값을 출력해 흰색·검정 값 확인 / 직진·정지 / 좌·우 보정 추가.
  - 디버깅: 좌·우 회전을 반대로 넣은 코드 / 둘 다 검정일 때 처리가 없어 선 끝에서 멈추지 않는 코드 / 센서 0·1 의미를 반대로 이해한 코드(원본은 검정 0, 흰색 1이라 모듈마다 확인 필요).
- **교과 융합**: 과학(빛의 반사와 흡수, 적외선·전자기파), 실과(물류 자동화, 로봇), 사회(산업과 인프라, SDG 9), 수학(경우의 수 2×2). 활동: 여러 색 종이의 반사값 측정표 / 우리 학교에 라인트레이서를 둔다면 어디에 쓸지 설계.
- **예상**: 110분 1~2회, 난이도 중.
- **주의**: 트랙 바닥 테이프(검정 절연테이프 폭 1.5~2cm), 햇빛이 센서 값에 영향.

### W09 장애물 감지 자동차 & RC카 (53장, 수정본 기준)

- **학습 목표(원문)**: "초음파 센서로 장애물을 감지하고 라디오통신으로 마퀸을 제어할 수 있어요."
- **활동 흐름**
  - 도입: [9. 산업, 혁신과 인프라] → "장애물을 감지하고 스스로 피하는 자동차, 무선으로 조종 가능한 RC카를 만들어봅시다."
  - 복습: 초음파 원리(2~400cm, "아주 정확하지는 않습니다").
  - 전개 1(`w9_장애물 감지 자동차`): 마퀸 초음파 블록 → [거리] 변수. "로봇 청소기의 움직임을 상상해 봅시다" → "뒤로 살짝 후진한 후 우회전". 무한반복: 거리 저장 → 직진 → 거리 20cm 이하이면 500ms 후진, 200ms 제자리 우회전.
  - 전개 2(`w9_마퀸라디오통신`): 조작표 A 직진(go), B 후진(back), A+B 멈춤(stop), 왼쪽 기울임 좌회전(left), 오른쪽 기울임 우회전(right). 라디오 그룹(0~255, "그룹을 설정해야 다른 그룹과의 충돌을 막을 수 있어요"), 송신/수신 블록(숫자·변수값·문자열). 두 명이 한 팀(송신용 micro:bit + 마퀸 수신용). 수신: 문자열 비교 else-if("비교할 때는 문자열의 비교니까 "(따옴표)가 있는 비교연산을 사용하자!"), left/right는 750ms 회전 후 직진.
  - 정리(추가 미션): 송신은 기울기(로고 위/아래/왼쪽/오른쪽/흔들림)와 숫자 전송(receivedNumber), 수신은 로고 위 전진, 아래 후진, 왼쪽·오른쪽 회전, 흔들림 정지.
- **코드 핵심**: 거리 조건, 시간 기반 동작, 무선 통신(그룹·송신·수신 이벤트), 문자열/숫자 프로토콜, else-if.
- **센서·부품**: 마퀸(초음파, 모터), micro:bit 2대(라디오, 가속도).
- **ESP32 전환 판정: 장애물 차량은 불가(차량 구입 시 가능), 무선 조종은 일부 변경으로 가능**
  - 라디오 → **ESP-NOW**(MicroPython `espnow` 모듈, 짝 보드의 MAC 주소 등록 = 라디오 그룹 역할). 대안: BLE(키트 튜토리얼 2-2-01~03 BLE 제어 예제), WiFi 웹서버(2-2-05). 초등에는 ESP-NOW가 원본 구조(보내기/받으면)와 가장 비슷.
  - 기울기 제스처 → **조이스틱**(X/Y로 전후좌우, 누르기 = 정지) 또는 틸트 스위치.
  - 차량 없이: 수신 보드가 서보(방향)와 팬 모터(전진 세기)를 움직이거나 OLED에 명령을 표시하는 "무선 조종 시험대".
  - 장애물 회피 로직은 차량 없이도 "후방 감지기"(초음파 + 버저, 키트 2-4-22 Astern Detector)로 축소 가능.
- **모듈·핀 제안**: 송신 보드 — 조이스틱 X ADC IO36, Y ADC IO39, 누르기 IO26(PULL_UP), 버튼 IO14. 수신 보드 — 서보 IO4, 팬 IN+ IO13 / IN- IO12, OLED SDA21/SCL22. (차량 시 W07 모터 핀 배치)
- **트랙 수업 전환안**: **새 챕터 "무선 조종기(ESP-NOW)"** — 블록랩에 통신 블록(보내기/받으면/짝 등록) 신설 필요. 장애물 회피는 차량 단원 세 번째 챕터.
  - 문제 만나기: "사람이 들어가기 위험한 곳의 로봇을 멀리서 움직이려면 신호를 어떻게 보낼까?"
  - 조건 분석: 받은 말(go/back/left/right/stop) → 동작.
  - 미션: 버튼을 누르면 짝 보드 LED 켜기 / 조이스틱 방향을 문자열로 보내고 받아 OLED에 표시 / 받은 명령으로 서보·팬 움직이기 / (추가) 문자열 대신 숫자로 보내기.
  - 디버깅: 짝의 MAC 주소를 잘못 넣어 신호가 안 가는 코드(원본 "그룹" 충돌과 같은 개념) / 문자열 비교에서 따옴표 빠짐·대소문자 다름("Go" vs "go") / 받은 bytes를 문자열로 바꾸지 않아 비교가 늘 거짓인 코드.
- **교과 융합**: 과학(전파·소리의 전달, 초음파 반사), 사회(재난 로봇, 산업 자동화, SDG 9), 국어·정보(약속된 신호=프로토콜, 모스부호). 활동: 짝과 "명령어 사전" 만들기 / 로봇 청소기 회피 규칙을 순서도로 그리기.
- **예상**: 무선 조종 110분 2회, 장애물 회피(차량) 110분 1회, 난이도 상.
- **주의**: 보드 2대 필요(팀 구성), 같은 교실에서 다른 팀 보드와 혼선 → MAC 주소 확인 절차, 차량 낙하.

|---|---|---|---|
| 상 | 안전선풍기(W03) | 7장+10장 사이 새 챕터 | 키트만으로 완성, 이미 있는 팬(13/12)·초음파 코드를 그대로 재사용, "모드 변수·범위 조건"이라는 새 개념이 분명 |

| 중 | 무선 조종기(W09 RC 부분) | 새 챕터(통신) | ESP-NOW로 원본 구조 유지 가능, 단 보드 2대·통신 블록 신설 필요 |
| 중 | 폭탄 피하기(W04) | 9장 OLED 뒤 새 챕터 | 동시 실행이 없어 시간 비교·리스트가 필요 → 난이도 상, 메모리 게임 다음에 |
| 중 | 센서 사용법(W01) | 각 챕터 원리 단에 흡수 + 부저/가변저항 짧은 챕터 | 센서 카드 활동은 좋지만 독립 차시보다 분산이 효율적 |
| 하 | 마퀸 움직이기·라인트레이서·장애물 회피·따라오는 차(W07~W10 예시) | 차량 구입 시 새 단원 | 섀시·기어모터·드라이버·라인 센서 구입 필요. 구입 전에는 방향지시등/사이렌(3장 확장), 반사 실험(포토레지스터), 후방 감지기(초음파+버저)로만 일부 살림 |
| 그대로 | AI Intro(W04·W07), 자율 프로젝트(W10·W11) | 문제 만나기 이야기 / 성찰 단계 | 보드와 무관, SDGs 기획서·회고 문항을 트랙에 그대로 |

### 3-2. 버려야 하는 것(또는 대체해야 하는 것)

- micro:bit 5x5 LED 매트릭스의 아이콘(하트·해골·화살표)·좌표 plot·숫자 표시 → OLED/7세그먼트/LED로 대체.
- MakeCode 게임 블록(스프라이트, 닿았는지, 게임 점수/게임 종료) → OLED 직접 그리기 + 좌표 변수로 재구성.
- "무한반복 여러 개"로 병렬 실행하던 방식 → 한 반복 안에서 시간 비교(`ticks_ms`) 또는 asyncio.
- 내장 가속도·로고 방향·흔들림 제스처 → 틸트 스위치/조이스틱.
- 버튼 A+B 동시 누르기 이벤트 → 별도 버튼 또는 조이스틱 누르기.
- MakeCode 음악 블록(템포, 1/4박, '높은 미') → 주파수표 + 직접 만든 함수.
- maqueen 확장 블록, neopixel 확장 블록(링·RGB 4구), micro:bit 확장보드 핀 이슈(v2 16번 핀, VCC 5V 스위치) 설명.
- 라디오 그룹 0~255 → ESP-NOW MAC 짝 등록으로 개념만 이어받기.
- W05 체크리스트의 "에뮬레이터" 항목 → 블록랩 가짜 보드(`?device=fake`)나 실보드 확인으로 바꾸기.

### 3-4. 교과 융합 주제 묶음

1. **소리와 거리 — "보이지 않는 것을 듣는 기계"**: 스마트 지팡이, 안전선풍기, 후방 감지기(장애물). 과학(소리의 성질, 초음파 반사), 수학(비례: 거리와 소리 간격, 범위 조건), 사회·도덕(장애 이해, 생활 안전).
2. **빛과 색 — "에너지를 아끼는 빛"**: 스마트 무드등, 빛 반사 실험(라인트래킹 원리), 지팡이 야간 LED. 과학(빛의 3원색, 반사와 흡수, 적외선), 미술(색과 감정, 조명 디자인), 수학(구간 나누기·비례 변환), 사회(SDG 11 에너지).
3. **전기와 움직임 — "바람과 바퀴"**: 안전선풍기 PWM 세기, (구입 시) 전기차 주행·회전. 과학(전기의 이용, 물체의 운동·속력), 수학(각도, 시간-거리), 실과(수송·로봇), 사회(SDG 7 청정에너지).
4. **데이터와 놀이 — "기억하고 피하는 게임"**: 메모리 게임, 폭탄 피하기. 정보(리스트·함수·매개변수·난수), 수학(경우의 수, 좌표, 평균), 보건(치매 예방, 감염병 예방), 체육(반응 속도).
5. **연결과 협력 — "멀리서 움직이는 로봇"**: 무선 조종기(ESP-NOW), 자율 프로젝트. 과학(전파), 국어(약속된 신호·설명하기), 사회(재난 로봇, SDG 9).
6. **SDGs 문제 해결 프로젝트(전 과정 공통)**: 매 덱 도입의 퓨처비 챌린지 흐름(SDG 10·3·11·7·9)을 트랙 **문제 만나기**에, W10 기획서 4문항을 **설계**에, W11 회고 5문항을 **성찰**에 그대로 대응시키면 과정 전체가 하나의 사회 문제 해결 프로젝트로 묶인다.

> 참고: 교과 단원명은 일반적으로 알려진 초등 과학·수학 단원 내용(소리의 성질, 빛의 반사, 전기의 이용, 물체의 운동, 비례식 등) 기준이며, 2022 개정 교육과정 학년·단원 번호는 학교 교과서로 확인 필요.
